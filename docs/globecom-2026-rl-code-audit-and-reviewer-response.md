# GLOBECOM 2026 optimisation-method audit and revision guide

## Finding

The public repository `SeunOdusole180/uav-isac-livestock-monitoring` does not
implement reinforcement learning or deep reinforcement learning. Its offline
method is random-forest-assisted black-box optimisation:

1. `offline_rl_analysis.py` reads complete-run rows from `run_summary.csv`.
2. Its input is a 28-dimensional configuration vector and its target is the
   scalar `Jfinal`.
3. It fits `RandomForestRegressor(n_estimators=300, max_depth=8,
   min_samples_leaf=2, random_state=42)`.
4. It samples 50,000 configurations uniformly, applies simple speed/altitude
   constraints, predicts `Jfinal`, and selects the five largest predictions.
5. ns-3 evaluates those candidates; the intended outer loop appends the
   measured rows and retrains the surrogate.

There is no state-transition dataset, policy, value function, Q-function,
Bellman target, discount factor, replay buffer, actor, or critic. Each ns-3 run
is a terminal black-box evaluation. Calling this “offline DRL” invites exactly
the reviewers' requests for an algorithm and MDP that the code cannot supply.

The drop-in LaTeX replacement is in
`docs/globecom-2026-rf-optimisation-revision.tex`.

## Code/paper inconsistencies that must be resolved

| Item | Public code | Current paper/thesis wording | Required correction |
|---|---|---|---|
| Method | Random-forest regression plus candidate ranking | Offline RL/DRL | Rename to random-forest-assisted surrogate optimisation throughout, including abstract, keywords, Sections I/IV/V/VI, captions, and response letter. |
| Decision size | The RF uses 28 variables: 4 sensing, 4 alpha, 8 speed, 8 altitude, and 4 update intervals. The ns-3 executable also exposes UE and gNB transmit powers. | The thesis defines a 30-variable vector including both transmit powers. | Say that the simulator exposes 30 candidates but the released RF optimises only 28. Use 28 for the reported optimiser unless both powers are added to `FEATURES` and the experiments are rerun. |
| RF settings | 300 trees, depth 8, leaf size 2, seed 42 | Not stated | Report all settings and LOOCV MAE. |
| Candidate rule | 50,000 uniform samples; take predicted top five | Described only as “guided” | State the sampling, feasibility repair, de-duplication, ranking, and batch size. |
| Objective weights | $3P+3T-2R-D-L$ | Thesis says $3P+2T-3R-D-L$; paper gives symbols only | Reconcile against the exact dataset-generating executable. Do not mix results generated with different weights. |
| Normalisation | Fixed clipping references: 0.002 Mbit/s, 30 m, 20 ms, 100% | Thesis says dataset min--max normalisation | Use the fixed references if the reported CSV was generated by the public C++ code. |
| Energy constraint | RF candidate selection does not inspect predicted or measured per-UAV energy | Paper states a hard battery constraint | Implement and document rejection/filtering, or change the claim to an a-posteriori energy comparison. |
| Model persistence | Offline script does not call `joblib.dump` | README/xApp says `offline_rf_model.pkl` is saved/loaded | Add explicit persistence in the experiment code or remove the claim. |

The objective and constraint discrepancies are not cosmetic: changing them
changes which configuration is optimal. Verify the executable and CSV used to
produce Tables II--III before finalising the replacement text.

## Suggested response to Reviewer 1, Comment 5

> Thank you for identifying the ambiguity in our optimisation description. An
> audit of the implementation showed that “offline reinforcement learning” was
> imprecise terminology. The implemented method is a random-forest-assisted
> surrogate optimiser: a 300-tree random forest learns the mapping from the
> 28-dimensional UAV configuration to the terminal mission score, ranks 50,000
> feasible sampled candidates, and proposes the five highest-scoring unseen
> configurations for ns-3 evaluation at each round. We have renamed the method
> throughout and added the decision vector, training hyperparameters,
> cross-validation procedure, feasibility rules, candidate-selection rule,
> stopping condition, and pseudocode in Section IV. Because each simulation is
> an independent terminal black-box evaluation and the implementation contains
> no sequential state transitions or policy/value learning, an MDP formulation
> would be artificial and misleading; the revised manuscript explicitly states
> why an MDP does not apply.

## Suggested response to Reviewer 2, Comment 2

> We added the rationale for the selected optimiser. A complete ns-3 mission is
> expensive, the objective has no analytic gradients, and the 28 variables
> interact nonlinearly. A random forest can learn this small tabular dataset,
> represent nonlinear interactions, tolerate heterogeneous parameter scales,
> and rank many candidates without additional simulator calls. Model-free RL
> would require a genuine sequential control interface and substantially more
> interaction data, neither of which is present in the offline experiment.

  optimisation.”

- Section IV title and body: replace the vague paragraphs with the supplied
  LaTeX section.

  procedure.”
- Section VI: replace “offline DRL optimisation approach” with
